VERY SIMPLE EXPLANATION
------------------------
This project has five important parts:

1. Docker runs the databases and the message system.
2. The producer creates fake banking transactions.
3. The consumer scores each transaction for fraud.
4. FastAPI saves the results and gives data to the dashboard.
5. Ollama reads the evidence and writes a short analyst explanation.

You do not need to type all commands in one terminal. Use one PowerShell
window for each terminal section below.

If you only want the main demonstration, use Terminals 0, 1, 2, 3, 4, 5,
and 6 in that order.

What the words mean:

- producer = creates and sends fake transactions
- consumer = receives transactions and calculates risk
- FastAPI = the backend web server
- PostgreSQL = stores transactions and alerts
- Neo4j = stores account relationships
- SHAP = explains why the model gave its score
- Ollama = local AI that writes the human explanation
- dashboard = the web page for the lecturer

The dashboard is the main thing to show your lecturer. The terminal is only
used to start the system and prove that the dashboard uses the real backend.

================================================================
INVESTIGATE ALL THREE SYNTHETIC TRANSACTIONS WITH OLLAMA
================================================================

$transactionIds = @(
  "synthetic-000000009000",
  "synthetic-000000009001",
  "synthetic-000000009002"
)

foreach ($transactionId in $transactionIds) {
  Write-Host "=============================================="
  Write-Host "Investigating $transactionId"
  Write-Host "=============================================="

  Invoke-RestMethod `
    "http://127.0.0.1:8000/api/v1/investigations/$transactionId" |
    ConvertTo-Json -Depth 20
}

Each investigation uses:

transaction
  -> alert
  -> XGBoost score
  -> SHAP explanation
  -> Neo4j graph lookup
  -> Ollama qwen3:14b interpretation
  -> final investigation response

The Ollama model may take time to respond, especially during its first load.


================================================================
IF THE DASHBOARD SAYS STATUS: ERROR:RUNTIMEERROR FOR OLLAMA
================================================================

This means the fraud model worked, but the local AI explanation did not.
The score, SHAP explanation, PostgreSQL data, and Neo4j data can still work.

Use these checks in a new PowerShell terminal.

CHECK 1 - Is Ollama running?

Invoke-RestMethod http://127.0.0.1:11434/api/tags

If this command gives a connection error, start Ollama:

ollama serve

Leave that terminal open. Then continue with CHECK 2.

CHECK 2 - Is the qwen3:14b model installed?

ollama list

If qwen3:14b is not listed, download it:

ollama pull qwen3:14b

This download can be large and can take time.

CHECK 3 - Can Ollama answer a simple question?

ollama run qwen3:14b "Reply with the word OK only."

The answer should contain OK. If this command fails, the problem is Ollama
or the model installation, not the dashboard.

CHECK 4 - Restart FastAPI after Ollama is ready

Go back to Terminal 2. Press Ctrl+C to stop FastAPI. Start Terminal 2 again
using the same FastAPI command. FastAPI must be running while Ollama is ready.

CHECK 5 - Open the dashboard again

Refresh the browser with Ctrl+Shift+R. Click one alert and wait. qwen3:14b
can take a while during its first response.

If the dashboard still shows ERROR:RUNTIMEERROR, run the API command below.
It shows the more detailed error in the terminal running FastAPI:

$transactionId = "synthetic-000000009000"
Invoke-RestMethod `
  "http://127.0.0.1:8000/api/v1/investigations/$transactionId" |
  ConvertTo-Json -Depth 20

Look at the FastAPI terminal for the detailed Ollama error. Common causes are:

- Ollama was not running.
- qwen3:14b was not installed.
- Ollama was still loading the model.
- Ollama took longer than the request timeout. Terminal 2 now sets the timeout
  to 300 seconds because qwen3:14b can need extra time for full evidence.
- Ollama returned text that was not valid JSON.

For the lecturer, explain this honestly if it happens:

"The fraud model and evidence pipeline are working. The optional local LLM
interpretation is unavailable because Ollama did not return a valid response."

================================================================
WHAT TO EXPLAIN TO THE LECTURER
================================================================

1. The producer creates transactions and publishes them to Redpanda/Kafka.
2. The consumer loads the XGBoost model and scores each transaction.
3. A score above 0.55 creates an alert in PostgreSQL.
4. SHAP explains which features increased or decreased the score.
5. Neo4j provides account and transaction relationship evidence.
6. Ollama qwen3:14b converts the retrieved evidence into an analyst explanation.
7. The React dashboard is the investigator interface.
8. The terminal is the API verification interface.
9. Both views must use the same transaction_id when comparing results.
10. graph: null means graph evidence was unavailable; the LLM must not invent it.
11. A fraud alert is a high-risk signal for human review, not legal proof of fraud.

Recommended lecturer demonstration order:

1. Show the architecture.
2. Start infrastructure and FastAPI.
3. Show /health and /docs.
4. Start the consumer.
5. Publish exactly three synthetic transactions.
6. Show the three risk scores and alerts.
7. Open the dashboard.
8. Click synthetic-000000009000, then synthetic-000000009001,
   then synthetic-000000009002.
9. Show that the selected transaction ID and details change.
10. Show the SHAP explanation and Ollama interpretation.
11. Explain graph: null honestly for synthetic records.
12. Optionally show a real Neo4j-backed transaction.
